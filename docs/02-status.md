## 2. 云端为什么只有"连接"

`HARDWARE/onenet/onenet.c` 全文被注释，`ESP8266_SendData()` 同样被注释，全工程搜不到 `AT+MQTTPUB`。
`main.c` 里原本调用的 `OneNet_SendData()` 没有任何定义 —— 这就是原始工程编译不过的原因之一，整理时已注释掉并标了 `TODO`。

要做完上报，最小路径是：

1. 在 `esp8266.c` 里加一个 `AT+MQTTPUB=0,"<topic>",<qos>,0` 的发送函数（或 `AT+MQTTPUBRAW` + 数据）；
2. 用 `cJSON`（原工程 `HARDWARE/onenet` 里有，但已作为第三方移除）或手拼 JSON，字段对齐 OneNET 物模型；
3. 在 `main.c` 循环里替换掉 `TODO` 那行，并把 `ESP8266_Clear()` 的时序挪到发送之后。

## 3. 三个必须知道的坑

| 坑 | 现象 | 原因 |
| --- | --- | --- |
| 引脚冲突 | AS608 与 ESP8266 抢 PA2/PA3 | 两套驱动都用了同一组串口引脚，只能二选一 |
| UART1 无 ISR | K210 一发数据就死机 | `UART1_Init()` 开了接收中断，但 `K210.c` 没加入工程 |
| 初始化无超时 | 没有 Wi-Fi 时上电卡死 | `ESP8266_Init()` 每步 `while(SendCmd(...))` 无限重试 |

## 4. 下一步建议（按性价比排序）

1. **把上报打通**：这是"能上云"和"只是连上了"的区别，工作量最小、收益最大；
2. **修引脚冲突**：AS608 换到 UART1 或软件串口，顺便把指纹考勤做成真功能；
3. **给 ESP8266 加超时与重连**：断网后能自己恢复，不靠断电；
4. **OLED 加刷屏函数**：`OLED_Refresh()` 把 `OLED_GRAM` 推回屏，贴图/表情包才有效果；
5. 再考虑 SGP30 基线标定、MPU6050 姿态、舵机动作——这些是锦上添花。
